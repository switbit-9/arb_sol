Here's what your client needs to compute for each program's pool_fees entry, all normalized to millionths (denominator = 1,000,000):

Pump AMM
pool_fees[0] = fee_rate (dynamic, tier-based on market cap)
Source: Compute from the 24-tier table using current vault balances
Already in millionths natively
Meteora DAMM V1 / DBC
pool_fees[0] = trade_fee_numerator
Source: Pool account data at offset 322 (trade_fee_numerator u64) / offset 330 (trade_fee_denominator u64)
Calculation: (trade_fee_numerator * 1_000_000) / trade_fee_denominator
The on-chain denominator is per-pool, so you must normalize
Meteora DAMM V2
pool_fees[0] = fee_a_to_b
pool_fees[1] = fee_b_to_a
Source: pool.pool_fees.base_fee.cliff_fee_numerator (u64)
Native denominator: 1,000,000,000 (billion)
Calculation: cliff_fee_numerator / 1_000 (divide by 1000 to go from billionths to millionths)
Note: fees can differ per direction. If they're the same, both values are equal
Meteora DLMM
pool_fees[0] = total_fee (base + variable)
Source: lb_pair.get_total_fee() which combines base_fee + variable_fee (volatility-based)
Native denominator: 1,000,000,000 (FEE_PRECISION)
Calculation: total_fee / 1_000 (divide by 1000)
This is the dynamic one — variable fee changes based on volatility, so you must recompute it client-side each time
Orca Whirlpool
pool_fees[0] = fee_rate
Source: whirlpool.fee_rate (u16, hundredths of a basis point)
Already in millionths natively (e.g. 3000 = 0.3%)
If adaptive fees are enabled: must compute from oracle data (volatility accumulator, decay periods). The static fee_rate alone isn't enough — add the adaptive component
Raydium AMM
pool_fees[0] = swap_fee_numerator
Source: amm_config.trade_fee_rate (u64)
Native denominator: 1,000,000
Pass as-is — already in millionths
Raydium CLMM
pool_fees[0] = trade_fee_rate
Source: amm_config.trade_fee_rate (u32)
Native denominator: 1,000,000
Pass as-is — already in millionths
Raydium CPMM
pool_fees[0] = trade_fee_rate
pool_fees[1] = creator_fee_rate
Source: amm_config.trade_fee_rate and amm_config.creator_fee_rate (u64)
Native denominator: 1,000,000
Pass as-is — already in millionths
Summary
Program	Fees	Native Denom	Conversion
Pump AMM	[fee_rate]	1M	as-is (compute from tier table)
DAMM V1 / DBC	[trade_fee]	per-pool	num * 1M / denom
DAMM V2	[fee_a→b, fee_b→a]	1B	÷ 1_000
DLMM	[total_fee]	1B	÷ 1_000 (recompute each swap)
Orca	[fee_rate]	1M	as-is (+ adaptive if enabled)
Raydium AMM	[swap_fee]	1M	as-is
Raydium CLMM	[trade_fee]	1M	as-is
Raydium CPMM	[trade_fee, creator_fee]	1M	as-is
The only ones requiring conversion are DAMM V1 (variable denominator), DAMM V2, and DLMM (both 1B → 1M). The dynamic fees to watch out for are DLMM (volatility) and Orca (adaptive).
